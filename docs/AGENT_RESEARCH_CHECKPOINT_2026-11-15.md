Smart Jobseeker remains an integrated prototype. Complete autonomous application
workflows, rather than field accuracy or low latency, determine readiness. The
current committed baseline is `90b5b1063af546e2544195394fec9b466f107060`.
This checkpoint neither authorizes submission nor publishes a release.

## Current product evidence

- The mixed development rehearsal verified **9/9 known fields**, entered **0/2
  unknown answers**, and retained nine immutable progress records. It stopped at
  the review transition; whole-workflow completion is **not qualified**.
- The actor already combines native inspection, independently observed local
  vision, source-bound answers, candidate revision checks, typed controls and
  bounded anonymous public research. These mechanisms do not establish universal
  coverage or reliable autonomous research-assisted repair.
- The immediate gap is generic navigation intent and independently checked final
  review. Adding another button-label synonym would leave the architecture gap.
  Real employer forms remain read-only; interactive qualification uses isolated
  fictional or offline fixtures.

`4af51b3542f775b0a8e4b310bfb3f17e01c306c9`. The owned local download completed,

`56d747cb510c031f215eea0c2cef98662ef76c95177667b11b0080e2a63f7bf0`.
The installed inventory reports **14,077,541,042 bytes** including its layers.
This is a download/capability declaration, not successful visual inference or
model promotion.

The download used a private store and bounded owned runtime. The process tree
drained; the pre-existing shared runtime remained unchanged. No default model,
shared model store, autostart entry or service was changed.

Before inference, six component probes were frozen with exact image/input hashes:
two blind transcriptions of historical fictional native captures, specific-source
quantity extraction, refusal of unsupported sponsorship advice, refusal of an
unstated unit conversion, and semantic review intent without action authority.
These are development probes, **not held-out cases or whole workflows**. Both
models receive the same inputs, schema, 4,096-token context and generation
settings. Responses, completion metadata, model identity, resource observations
and failures remain private. Results are recorded below only after native exit
and cleanup have been verified.

The completed [capability experiment](g1/MODEL_CAPABILITIES_2026-11-15.md)
identified missing native renderer/parser configuration in the GGUF import.
With the official configuration, actual thinking/final separation, visual reads
and a typed tool proposal work; explicit advertised `xhigh` was exercised.
Strict six-case results varied with configuration, and maximum effort regressed
one visual result relative to a lower setting. No model/default promotion is
justified. The core capability probe now refuses final-answer-only evidence of
enabled thinking and incorrect or incomplete structured-probe output.

## Next implementation and acceptance order

1. **Generic navigation and review.** Let the local planner reason about current
   native-bound control candidates and page context, including unfamiliar wording,
   repeated controls and conditional branches. Keep semantic intent separate from
   execution authority. Require independent current native/visual final-summary
   checks; an empty form, completed field list or promising button label cannot
   declare the workflow complete.
2. **Representative paired workflows.** Freeze varied multi-step, embedded,
   repeated and custom-control families before tuning. Include unfamiliar held-out
   families and manual walls in explicit denominators. Compare repeated complete
   journeys, exact answer/document truth, abstentions and unsafe entries. Do not
   promote a model solely from these six component probes or vendor benchmarks.
3. **Bounded repair and reusable learning.** Improve the existing anonymous
   runtime research loop on retained real failures. Advice may propose a scoped
   repair; it cannot establish candidate facts, authorize a write or waive failed
   validation. Reuse only source-bound lessons with current-state checks,
   expiry/revocation and held-out regression evidence. Keep model evaluation free
   of responses cached from another model.
4. **Connect full candidate journeys.** Exercise discovery through reachable
   application route, tailored and visually checked PDFs, contacts/history/facts,
   multi-step entry, final review and immutable attempt archive. Keep original ads,
   attachment hashes, answers and failed/partial captures together.
5. **Complete release gates.** Qualify consequential-action isolation separately,
   then missing-dependency setup/repair on clean Windows hosts, resource ownership,
   responsive UI/zoom/drag states, encrypted storage/recovery and detector results.
   The user decides whether and when to release.

Research continues at capability/design checkpoints and when retained failures
suggest a missing mechanism. Each useful finding should change a concrete
implementation or evaluation, with its source/version retained. Neither vendor
marketing nor a larger parameter count establishes superiority. Correctness and
complete-workflow coverage remain primary; latency tuning follows them.
