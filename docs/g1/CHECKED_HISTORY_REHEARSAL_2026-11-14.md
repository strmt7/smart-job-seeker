## Connected path

The authenticated coordinator loads the saved profile; public capture-worker
requests still contain only a bound snapshot digest, not candidate values,
history records, credentials or answers. Only records explicitly marked checked
are projected. Unchecked entries, other profile settings and instructions are
excluded. History-only mode supplies no fictional contacts or documents.

Version-3 candidate snapshots bind the canonical checked history, full source
profile revision, job identity and separately selected contacts/PDFs. Versions
1/2 remain readable. Loading validates the header size/schema/digest, canonical
checked-only history and job binding before inference or browser admission.
Dates retain supplied precision; an absent month never becomes January.
Candidate snapshots and archived answers remain immutable and plainly visible
in each attempt folder, alongside the existing encrypted profile/database.

The actor reuses the existing whole-form history planner. Its first model call
classifies each question's subject, period and component without candidate
values. Local code resolves only a uniquely eligible checked record, preserving
current/completed distinctions, date precision and ambiguous rankings. A separate
model check assesses the proposed value against the actual question. Before
entry, local code re-resolves the record role/component, exact typed value and
source digest. Model output never supplies new candidate values or authorization.

Existing contact-review exclusions, native sensitivity/credential guards,
third-person exclusions, field types, text limits, native identity/file/value
checks, and independent before/after image review still apply. Another actor's
contact value is not overwritten. Unavailable records/components, unconfirmed
periods, unsupported date/number controls, overly long values or unclear answers
stay in review. The current rehearsal's bounded entry limit and incomplete
workflow criteria remain explicit; it is not arbitrary history completion.

Each attempted plan is retained as a checksum-bound
`answers/history-plan-NNN.json`; performed history checks are separately retained
in `answers/history-entries-NNN.json`. The result keeps source record/component,
selection basis, source/profile/history/schema digests, actual entry and visual
observations distinguishable. Archive failures stop further entry, not silently
convert to successful accounting. Public technical research stays anonymous:
checked-history values join the local outbound-reference guard without entering
the technical question or changing global job-search query semantics.

## Corrections and views

A successful profile correction signals cancellation of a running rehearsal
bound to the old profile. The task remains tracked until worker teardown is
observed; no automatic retry is scheduled. An unconfirmed native shutdown remains
a failure, even when the input was invalidated. Completed native results and
snapshots are retained. Status routes and paged archive views compare current
profile digests, displaying stale or unavailable input explicitly without
rewriting the old record. This is source-revision invalidation, not independent
verification of the person's career or document contents.
