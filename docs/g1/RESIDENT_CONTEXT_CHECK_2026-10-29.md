# Resident inference context check — 2026-10-29

Web-app structured inference now requests the context length reported for the single eligible resident Ollama model immediately before generation. It refuses absent, ambiguous, oversized, CPU-offloaded, or contextless resident-model reports. Visual inference uses the same check. The standalone adapter retains its existing default unless the caller opts into resident-context mode. The check is a snapshot, not a memory reservation: another client can change runtime state between the check and request, and the change cannot guarantee that the machine will never run out of memory.

Focused loopback fixtures verified that structured and visual requests include the reported 4,096-token context and that invalid residency reports are refused. The [fictional text check](resident-context-text-2026-10-29.txt) used the production form-suggestion path; the model again omitted the difficult given-name field and the application reported manual review. The [fictional visual check](resident-context-vision-2026-10-29.txt) transcribed a synthetic 16-field form and detected two intentionally different expected values. These are small functional checks, not broad model-accuracy or peak-memory measurements.

The live checks used local `qwen3.5:9b` Q4_K_M, digest `c97eb11d70b1acdc88af01eef566c1fe4f7fbe93eb1afc06871132f293ff425a`, with one fully GPU-resident model at a 4,096-token context. Before the text check, sampled free system memory was 25.13 GiB and dedicated GPU usage 10.74 GiB; before the visual check, 24.90 GiB and 10.74 GiB; a later sample was 25.06 GiB and 10.90 GiB. These are point-in-time samples, not continuous peaks. The ignored checks require external resource preflight and use a no-default-features build. No real candidate data, employer website or application submission was involved.
