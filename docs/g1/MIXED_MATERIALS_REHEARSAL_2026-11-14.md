# Mixed materials and native numbers — 14 November 2026

## Implemented scope

Native number inputs now participate in saved-page qualification filling. The
actor retains a distinct `number` kind, exact scalar/source/unit proof and native
min/max/step checks before entry and after focus. Numeric readback is exact;
telephone presentation equivalence does not apply. Post-entry native changes
invalidate the observation. The pixel reviewer checks an editable input category:
HTML number inputs can look identical to text inputs, so pixels are not presented
as proof of the hidden native type. The live schema establishes that type.

Corpus schema 4 adds explicit native-number truth while preserving schema 3's
structural control identities and exact values. Schemas 1–3 still reject that new
kind. No value/source/image criterion or earlier denominator was relaxed.

The offline actor now has a bounded **16-entry / 900-second** allowance. The
previous 8-entry / 300-second allowance was insufficient for the mixed case.
Model context, RAM admission, owned-job limits, section/action guards and the
read-only public-capture allowance are unchanged. Each attempted field writes a
new, hash-addressed `answers/progress-entries-NNN.json` checkpoint. These retain
observations if a later call or final report fails; they expressly do not prove
final review, present validity, submission or delivery. Later invalidation never
rewrites earlier checkpoint bytes. A checkpoint write failure stops further
entry and remains an explicit error.
