# Starting an existing local runtime — 2026-10-31

Settings can start an existing Windows Ollama executable without a visible console. It checks the loopback runtime endpoint first, leaves an existing service unchanged, and refuses to launch if the port is occupied by an unrecognized service. It searches the bundled location, standard per-user and program-files locations, and absolute PATH entries. The spawned process is limited to one loaded model and one parallel request, binds to IPv4 loopback, and does not itself load a model. It is left running after the app exits so the app does not stop a service another client may have begun using. A timeout does not prove the process stopped; the UI asks the user to check status before retrying.

A local live check recognized the already-running runtime without replacing it. A fictional loopback server test confirmed that an occupied non-runtime port is rejected, and a UI test covered the startup control. A separate live test launched an owned runtime process on an isolated loopback port with an empty temporary model directory, confirmed that it reported no resident models, checked that the existing service remained unchanged, and stopped only the owned process. This does not establish fresh-install or other-host behavior. This feature does not install Ollama; model downloads still require an existing runtime.
