# Framed cover-letter check — 2026-10-29

The cover-letter generator now requests a cited, evidence-based body from the model and supplies a separate opening from the saved job title and employer and a courtesy closing. The web editor displays that framing separately from the cited paragraphs and includes it in the editable text used for export. Missing or multiline job details fall back to a generic opening; the job-derived wording still requires review. CV drafts do not receive this framing.

The [fictional live run](production-cover-framed-2026-10-29.txt) used local `qwen3.5:9b` Q4_K_M, digest `c97eb11d70b1acdc88af01eef566c1fe4f7fbe93eb1afc06871132f293ff425a`. The model produced two short factual body sentences without the specific unsupported employer-attribution phrase observed previously. The returned result contained the separate opening and closing. Focused backend tests and a UI test checked framing, citations and editable text. This one simple example does not establish that model-generated body claims are supported, that the resulting letter is polished, or that all user templates and instructions are faithfully represented.

These are snapshots, not continuous peaks. The ignored live test requires external preflight, explicitly requests the preloaded context and uses the no-default-features build.
