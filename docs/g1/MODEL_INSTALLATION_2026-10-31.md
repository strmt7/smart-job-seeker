# Local model installation — 2026-10-31

> Research evidence note (2026-11-02): Earlier Crawl4AI captures predate correction of an upstream automation-masking default and browser identity. Their compliance with the no-stealth research configuration is not established; reverify source claims before relying on them as qualifying captures. See [implementation status](../../IMPLEMENTATION_STATUS.md).


Settings can request one of two reviewed local models from a running Ollama instance. The user chooses the model; the app sends a loopback-only pull request with insecure transport disabled, reads bounded streaming progress on a background thread, and shows progress for the current download part. It holds the local model-operation lease during the request. Existing model names are not intentionally replaced: the inventory is checked before requesting a pull, and an existing different manifest is reported as unchanged. A successful new download is checked against the reviewed manifest digest reported by Ollama; this is not an independent hash of all model bytes. A mismatch or interrupted response is reported and the runtime-managed files are left for inspection. Ollama stores the data in its configured model directory; the app does not know its available disk space and does not start the model after installation.

The operation can be recovered after a browser reload. Its network request has a one-hour limit; an interrupted request may have left partial files or continued in the runtime, so the UI directs the user to check inventory before retrying. Concurrent external clients can change runtime state between checks. Ollama itself still has to be installed and running; this feature does not provision it. No model was downloaded during these checks.

Mock loopback tests exercised chunked progress, normal completion, an incomplete stream, a changed reported digest, rejection of unreviewed names and preservation of an existing model. A live local check confirmed that the already-installed reviewed 12B model was recognized without issuing a pull. The [Ollama pull API documentation](https://docs.ollama.com/api/pull) describes the streaming request; a robots-checked Crawl4AI 0.9.5+flitzzip.portable2 capture returned HTTP 200, SHA-256 `1fd33f5fcca8a32d1e9faf1f46b05655dce87e233db8232ab3f69024c16f04bf`, retained locally at `target/ollama-pull-doc-20261031.json`. Mock tests do not establish reliability of a real multi-gigabyte download.
