# Focused form-field vision check — 2026-10-31

A fictional native datalist fixture exposes a populated Region field beside an empty field. The original whole-page transcription with `gemma3:4b` missed Region; an initial wider crop also failed. A tighter field-context crop and a prompt naming the field but withholding the expected value produced a matching transcription for Region while leaving the empty adjacent field unobserved in one run. This was an exploratory diagnostic, not a model selection or a reliability measurement.

The same focused fixture passed once using the previously used `qwen3.5:9b` Q4_K_M (`c97eb11d70b1`) at a 4,096-token context. The existing fictional placeholder check also passed once with that model. The model was reported as 100% GPU resident; one point-in-time sample during the run period reported 21.69 GiB free system memory and 12.45 GiB dedicated GPU use across the host. These samples are not peak measurements. The browser used a local fictional fixture and did not submit an application.

The focused inspection takes a bounded screenshot of the selected completed text or single-select field after scrolling, then checks the captured image again before and after live DOM verification. A missing, changed, clipped, obscured or ambiguous field requires manual review. The crop is not evidence that the rest of the form is correct, and neither a matching transcription nor a DOM check establishes correctness or submission approval. These two model runs do not establish repeatability, real-site accuracy, or suitability for every layout.

For a larger candidate, the official [Ollama Gemma 4 page](https://ollama.com/library/gemma4) describes its 12B model as accepting text and images and lists a 7.7–8.0 GB model size. The native, robots-checked Crawl4AI 0.9.5+flitzzip.portable2 capture returned HTTP 200, with SHA-256 `0a1cd93d9a483bc4a09038a9187f0e93efbe9187fcc9e9c4348ffc1fb467daac`, retained locally at `target/gemma4-model-research-20261031.json`. Model file size does not include all runtime memory or prove that the model fits the current host workload. The installed quantized 12B candidate was subsequently tested as described below.

The locally installed `gemma4:12b-it-q4_K_M` and `gemma4:12b-it-qat` variants were attempted sequentially with Ollama 0.40.13, a 4,096-token context, and no other resident model. Both failed during vision-projector initialization, before the fixture could be run. The first error also mentioned assistant context initialization; these messages do not establish a root cause. After the first failure the host showed 27.17 GiB free system memory and 5.81 GiB dedicated GPU use in a point-in-time sample. No comparison result is available for either 12B variant.

A diagnostic rerun identified the QAT model loading failure: setting `num_batch=64` caused the runtime to cap image tokens below the model projector's minimum. With Ollama 0.40.13, `num_batch=128`, a 4,096-token context and one loaded model, `gemma4:12b-it-qat` (`38044be4f923`) loaded fully on the GPU. A point-in-time sample showed 20.04 GiB free system RAM and 13.15 GiB total dedicated GPU use; it is not a peak measurement. The Q4_K_M variant has not been retested with the adjusted batch.

In separate single runs, the 12B QAT model passed the focused datalist, placeholder, deliberate mismatch and 16-field dense vision fixtures. It initially mapped an ambiguous contact question to the sole available email profile key. After a prompt revision requiring the requested information type to be identified, the model left two differently worded ambiguous contact fields for manual review while retaining a clearly labeled email suggestion in one local browser run. The previously used `qwen3.5:9b` also passed that expanded fixture once after the prompt revision. These limited fictional examples do not establish repeatability or accuracy on employer websites; model suggestions and visual results still require user review.
