# Resource-gated local model startup — 2026-10-31

The model inventory can start a user-selected installed GGUF model on Windows. Startup runs in the background, uses the existing single-model lease, checks that no model is resident twice, and does not initiate a download. It accepts a unique local inventory entry of 1–8 GiB whose name does not contain `cloud`. It requires one GPU with complete dedicated-memory observations and available system memory. The admission estimate reserves 8 GiB of system memory beyond the model file size and requires GPU free memory of at least 120% of the model file size plus 2 GiB. Requests use a 4,096-token context, batch 128 and two CPU threads; successful results require the runtime to report the selected model as the single fully GPU-resident model. Results can be recovered after a browser reload. An error after dispatch advises checking status before retrying.

These are conservative estimates and snapshots, not reservations or upper bounds on every model's runtime use. Other processes or runtime clients can change resource use between checks, so this does not guarantee freedom from swapping, eviction, or freezing. Multiple GPUs, unavailable performance counters, large or unknown models, and insufficient observed headroom are refused. Model installation remains external.

On one Windows host with an AMD Radeon RX 9070 XT, the startup path loaded `gemma4:12b-it-qat` (`38044be4f923`) and Ollama reported 100% GPU residency with a 4,096-token context. A subsequent point-in-time sample reported 19.75 GiB available system memory and 13.10 GiB dedicated GPU usage across the host; neither is a peak. A separate test confirmed that an already-resident model was left unchanged. A repeat immediately after unloading was refused when observed headroom had not yet recovered; a later repeat succeeded. No application was submitted. These limited checks do not establish behavior for other hardware or model architectures.
