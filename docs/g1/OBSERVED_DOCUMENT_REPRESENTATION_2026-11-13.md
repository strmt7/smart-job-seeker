## Request provenance and exact replay

The rendering engine's navigation Accept preference is observed in a separate,
owned, scriptless fictional HTTPS document inside the existing zero-capability
AppContainer. The sentinel has no person, form or external resource. Exactly
one anonymous bodyless Document request is required. Missing, repeated,
ambiguous, credentialed or malformed observations refuse the preference.
The native owner verifies engine files and shutdown. A private sidecar binds
the observed preference, engine-file digest and sentinel-manifest digest.

A bounded `PublicDocumentAccept` value passes to the existing native HTTP
client for document GETs. Robots and non-document assets retain their existing
request context. Documents cannot combine the preference with Origin, a body
or arbitrary headers. Syntax, size and ASCII/control checks refuse header
injection. The native writer parses its actual outgoing request and retains
the exact Accept value in `CapturedResponse`; response-only streams carry no
request proof. Source permissions, robots, DNS/TLS, redirects and byte/time
budgets remain enforced by the existing broker.

Snapshot variants can bind Accept and absence of X-Requested-With only for
proved anonymous GET HTML/navigation representations. The manifest retains
the actual native Accept, explicit absent-Origin context and any required
X-Requested-With absence. Unsupported selecting dimensions, credentials,
preflights, body indicators, unknown request evidence and wrong MIME/scope
remain review-required. Repeated Vary lines are combined as a bounded list,
retaining every selecting dimension; other duplicate headers remain refused.

Replay checks the actual paused Document request against these bindings.
Missing/different Accept values, XHR/fetch/style/image use, bodies, credentials,
Origin or conflicting headers cannot reuse the representation. Added metadata
is validated strictly; historical archives keep their original interpretation.
The implementation installs no browser header overrides. An earlier override
attempt failed real-engine matching and was removed; its failed receipts remain.
Typed refusal reasons expose the mismatched category without recording header
values or candidate information.

This follows the request-field matching requirement in
[RFC 9111 section 4.1](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.1).
The implementation is an isolated archival renderer with no live fallback;
its results do not establish a general HTTP cache or server-side validation.
The isolated research receipt returned HTTP 200 and substantive content under
`target/document-representation-nhq26xaj/http-caching.native.private.json`.
A separate official protocol capture and bounded headless browser experiments
are retained there with the failed native alternatives.
